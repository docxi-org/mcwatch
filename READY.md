## 2026-09-07 · G3 · API каталога

`TODO.md`, действие G3 в части API. Одновременно закрывает остаток G2:
«похожие игры возвращаются API».

**Сделано.** `api/types.ts` — формы ответов отдельно от маршрутов, чтобы бриф
для интерфейса и сам интерфейс опирались на один источник. `repo/catalog.ts` —
запросы каталога. `api/games.ts` — три маршрута: `GET /api/games` (фильтр по
платформе, поиск по названию, четыре сортировки, постраничность с `total`),
`GET /api/games/:slug` (все поля ТЗ, оценки по платформам, резюме по обоим
видам, счётчики отзывов, похожие с названием и обложкой), `GET /api/platforms`.

**Решения.** Рейтинг игры для сортировки — максимум по платформам, не среднее:
разные платформы оценивают разные наборы изданий. Игры без оценки уходят в
конец рейтинга, а не возглавляют его. Похожие считаются на лету по всей базе:
при 44 играх это микросекунды, а хранить их значило бы пересчитывать при
появлении каждой новой игры. `/api/health` работает и без БД — иначе проверка
живости зависела бы от состояния хранилища.

**Проверка.** `pnpm check`: 150 тестов, из них 22 новых через `app.request()`
на временной БД. Живой сервер на собранной базе: 44 игры, сортировка по
метаскору даёт Elden Ring 90 → Onimusha 89 → Dawnwalker 88; карточка Onimusha
отдаёт четыре платформы с обоими скорами, оба резюме, 89 и 28 отзывов, двух
похожих; фильтр по Switch 2 даёт 12 игр, поиск находит, неизвестный slug — 404,
негодная сортировка — 400. Русский текст проверен на уровне сырых байтов ответа.

**Остаток.** Летсплея в карточке нет — поле появится на G6. SSE и принудительный
запуск — G5.
